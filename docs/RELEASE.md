# 배포와 되돌리기

## 배포

`main` 에 올리면 GitHub Actions 가 타입 검사 → 시험 → 빌드 → Pages 배포를
차례로 합니다. 사람이 누를 것은 없습니다.

```
git push origin main
```

배포 주소: <https://progh2.github.io/classic-bgm-dj-3d/>

빌드가 실패하면 배포되지 않습니다. 이전 판이 그대로 서비스됩니다.

## 올리기 전에

```bash
npm test                 # 단위 시험
npm run build            # 타입 검사 + 빌드
npm run catalog:check    # 카탈로그 점검
```

카탈로그를 건드렸다면 `catalog:check` 가 **문제 0건**이어야 합니다.
경고(해설 초안 등)는 판단에 맡깁니다.

## 손으로 확인할 것

기기를 바꿔 가며 아래를 훑습니다. 자동 시험이 잡지 못하는 것들입니다.

### 들어가기
- [ ] 안내인이 오른쪽에서 걸어 들어와 자리에 서고 목례한다
- [ ] 카메라가 문 쪽을 봤다가 가운데로 돌아온다
- [ ] 화면을 한 번 두드리면 인사가 소리로 들린다 (첫 조작 전에는 자막만)

### 듣기
- [ ] **맡길게** — 곡이 시작되고 안내판에 제목·연주자·진행이 나온다
- [ ] 재생기의 판이 돌고 톤암이 곡 진행에 따라 안쪽으로 들어간다
- [ ] **취향 고르기** — 네 질문을 지나면 고른 편성의 곡만 나온다
- [ ] 다음·이전을 누르면 안내인이 그 곡을 소개한다
- [ ] 멈추고 다시 틀면 말로 알린다
- [ ] 피아노곡이면 안내인이 피아노로 걸어가 앉아 연주한다. 다른 편성이면
      일어나 콘솔 뒤로 돌아온다

### 책자
- [ ] 프로그램북 왼쪽 면에서 곡을 한 번 누르면 오른쪽 면에 펼쳐지고,
      같은 곡을 다시 누르면 그 곡이 걸린다
- [ ] 다른 곡을 읽는 중에 곡이 바뀌어도 읽던 자리가 유지되고 리본이 뜬다
- [ ] 출처 안내서를 눌러 펼치고, 링크가 새 탭으로 열리며, 재생은 이어진다

### 기기와 방향
- [ ] 세로 휴대폰 — 조작부가 두 줄로 접히고 모두 손이 닿는다
- [ ] 가로 휴대폰 — 조작부가 한 줄로 펴지고 글자가 끊기지 않는다
- [ ] 취향 카드가 가로에서도 한 화면에 들어온다
- [ ] 두 번 두드려도 화면이 확대되지 않는다. 두 손가락 확대는 된다
- [ ] 큰 화면(전자칠판) — 단추가 64px 이상으로 커진다

### 키보드와 낭독기
- [ ] Tab 을 누르면 감춰진 층이 왼쪽 아래에 드러난다
- [ ] 키보드만으로 선곡·재생·곡 고르기·안내서 링크 열기가 된다
- [ ] 취향 카드가 열리면 초점이 카드 안에 머물고, Esc 로 닫으면 원래
      자리로 돌아온다
- [ ] 곡이 바뀔 때 낭독기가 제목과 작곡가를 읽는다

### 오래 두기
- [ ] 두 시간 틀어 두어도 곡이 이어지고 해설이 어긋나지 않는다
- [ ] 종료 예약 30분이 제대로 걸리고, 시각이 되면 마친다
- [ ] 브라우저 작업 관리자에서 CPU 와 메모리가 계속 늘지 않는다

### 무너질 때
- [ ] 네트워크를 끊으면 사실대로 알리고, 세 곡 연달아 실패하면 멈춘다
- [ ] 다시 연결하고 재생을 누르면 이어진다

## 되돌리기

배포된 판에 문제가 있으면 **고치는 것보다 되돌리는 것이 먼저**입니다.

```bash
git revert <문제 커밋>     # 되돌리는 커밋을 새로 쌓는다
git push origin main       # 자동으로 다시 배포된다
```

여러 커밋을 한꺼번에 되돌릴 때:

```bash
git revert --no-commit <옛 커밋>..HEAD
git commit -m "되돌리기: …"
git push origin main
```

배포는 2~3분 걸립니다. 그동안은 이전 판이 아니라 **문제 있는 판**이 서비스되고
있으므로, 급하면 GitHub 의 Actions 탭에서 이전 성공 배포를 다시 실행하는 편이
빠릅니다.

`git reset --hard` 로 역사를 지우지 않습니다. 이미 배포된 판을 되돌린 기록이
남아야 무엇이 언제 잘못됐는지 알 수 있습니다.

## 캐시

무거운 자료(모델·HDRI·결)는 서비스 워커가 기기에 담아 둡니다. 이 자료를
바꾸면 `public/sw.js` 의 `VERSION` 을 올려야 합니다. 올리지 않으면 이미
방문한 사람은 옛 파일을 계속 씁니다.

코드와 `index.html` 은 파일 이름에 해시가 붙어 새 배포가 바로 반영됩니다.
